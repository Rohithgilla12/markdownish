A field guide

What makes a CLAUDE.md
that actually works.

The context file is the most-read document in your repo — an agent re-reads it on every single turn. That makes it the highest-leverage prose you'll write all week, and the easiest to get wrong. Here's what earns its place, what to cut, and a few you can copy.

The principles

Seven things the good ones share

01

Every line is paid for, twice

It's re-read each turn and it crowds the context window. If a line doesn't change what the agent does, cut it. Brevity is correctness here.

02

Rules, not prose

Agents follow imperatives. "Prefer X over Y." "Never Z." Skip the narrative and the rationale unless the rationale changes the behaviour.

03

State the gate

Name the exact commands that mean "done" — pnpm test, cargo clippy. An agent that knows the gate checks itself before claiming success.

04

Draw the boundaries

What's off-limits, what's generated, what needs sign-off. "Don't edit dist/." "Ask before adding a dependency." Fences prevent the expensive mistakes.

05

Encode the conventions you'd correct

If you'd leave the same review comment twice, it belongs here. Naming, file layout, the comment style you hate. Write it down once.

06

List the non-goals

The things to resist — new abstractions, "while I'm here" refactors, reformatting untouched files. Saying no in advance is worth a paragraph of yes.

07

Keep it current

A stale CLAUDE.md actively misleads. When a convention changes, the file changes in the same commit. Treat it like code, because it runs like code.

What to cut

The bloat that creeps in

Every one of these is tokens spent on every turn for no behavioural change.

A full architecture essayThe agent can read the code. Link to a doc; don't inline it.
The entire dependency listIt's in package.json. Name only the ones with non-obvious rules.
Generic "write clean code" adviceIt changes nothing. Be specific or say nothing.
Onboarding prose for humansThat's what the README is for. CLAUDE.md is instructions, not a tour.
Banner comments and ASCII artPure token cost. The agent doesn't need the decoration.
Anything you haven't verified is trueA wrong instruction is worse than a missing one — it gets followed.
Annotated

A tight one, read closely

Forty lines. Notice how much behaviour each section actually controls.

● CLAUDE.md
# CLAUDE.md

A Next.js 15 app. Keep this tight — every line is re-read on every turn.

## Stack
- Next.js 15 (App Router), React 19, TypeScript strict
- Tailwind v4 + shadcn/ui · Drizzle ORM + Postgres

## Conventions
- Server Components by default. "use client" only for state/effects.
- Data access lives in lib/db/queries/, never inline in components.
- Prefer obvious code over clever code. Match the file's style.

## Workflow
- pnpm typecheck && pnpm test must pass before you claim it works.
- Commit only when asked. Branch off main. Conventional commits.

## Boundaries
- Don't touch app/(marketing)/ — separate design system.
- Secrets come from .env.local; never read or print them.

## Non-goals (resist unless asked)
- New abstractions for a single caller
- "While I'm here" refactors
The first line sets a scope and a discipline — the agent now knows to stay brief itself.
Conventions are phrased as imperatives an agent can follow, not preferences it has to interpret.
The workflow line names the literal gate, so the agent verifies before declaring success.
Boundaries fence off the two things that cause expensive mistakes: the wrong folder and secrets.
